# Repository Guidelines

## Project Overview
This repository implements the pipeline from the master's thesis "Deep learning-based animal re-identification for non-invasive wildlife monitoring and conservation." It builds a species-agnostic system that identifies individuals and estimates population size with no labels. The workflow: preprocess and optionally segment images (Grounded SAM2: GroundingDINO + SAM2), extract local features (DISK or KeyNet+AffNet+HardNet, optionally LightGlue), aggregate descriptors with PCA/GMM into Fisher vectors, optionally fuse global embeddings (ResNet50 or MegaDescriptor-L-384), then perform retrieval with geometric verification (RANSAC/MAGSAC with ratio/LightGlue/LoFTR matching). It supports training/evaluation on WildlifeReID-10k and field data from Medvednica trail cameras (wild boar and roe deer), and includes a Nested Importance Sampling estimator for counting.

## Build, Test, and Development Commands
- `python3 -m venv venv && source venv/bin/activate` and `pip install -r requirements.txt`.
- Training: `python main.py --train --ds ATRW --method keynet_hardnet --use_lightglue --fusion_signals fisher gv --save_eval`.
- Scratch MegaDescriptor-compatible training keeps the public model's 1536-D pooled Swin-L features: `python utils/train_megadescriptor_scratch.py --projection-head none --embed-dim 1536 --imagenet-init`. To fine-tune from the public MegaDescriptor model, add `--init-from-pretrained-megadescriptor` and use a small LR such as `2e-5`. Use `--projection-head linear_l2 --embed-dim 384` only as a projection-head ablation, not as the architecture-matched run.
- ELPephants embedding comparison: `python tools/evaluate_reid_embeddings.py --metadata-csv data/elpephants/processed_metadata.csv --images-root . --pretrained-megadescriptor` for the public baseline, and the same command with `--ckpt <checkpoint.pt>` for a trained scratch checkpoint.
- Full pipeline global embeddings can use a fine-tuned MegaDescriptor checkpoint with `--use_global_embedding --embedding_model megadescriptor-l-384 --global_ckpt <checkpoint.pt>`; cache names include the checkpoint path hash to avoid colliding with public MegaDescriptor embeddings.
- Counting: `python main.py --count --ds ATRW --num_vertices 150 --num_neighbors 20`.
- Batch runs: `bash run_final_comparisons.sh` and `python run_fisher_ensemble_batch.py --ds ATRW SealID`.
- PCA sweep (Fisher-only): `python utils/ablate_superpoint_fisher_pca.py --method superpoint|disk|aliked` (writes CSV under `evaluations/classifications/`).
- Few-shot metadata variants: `python utils/create_fewshot_datasets.py --datasets ATRW SealID --max_train_per_identity 3` (creates `atrw_fewshot`, `sealid_fewshot`; test split unchanged unless `--max_test_per_identity` is provided).
- Slides: `cd "docs/Final Thesis/presentation" && latexmk -pdf -interaction=nonstopmode main.tex`.
- Environment permissions: package/network installs are allowed for this workspace when needed. If root access is required, ask the user to run the corresponding `sudo` command.

## Data & Configuration Notes
- Expected dataset layout: `data/<DATASET>/dataset/` or `data/<DATASET>/images/`.
- Derived artifacts (PCA/GMM/Fisher vectors, embeddings) live under `data/<DATASET>/`.
- GPU is used when available; CPU fallback is supported.
- External test datasets not used in MegaDescriptor training: ELPephants (https://inf-cv.uni-jena.de/home/research/datasets/elpephants/) and SeaStarReID2023 (https://lila.science/sea-star-re-id-2023/). Use `datasets.<Name>.get_data("./data/<Name>")` to fetch.
- Grounded SAM2 requires checkpoints under `models/` (GroundingDINO config + weights, SAM2 weights).
- Segmentation prompts are configured for ATRW, ELPephants, and SeaStarReID2023 in `segmentation/__init__.py`.
- `--method` accepts multiple values for Fisher ensemble (e.g., `--method disk aliked`), while `--method ensamble` uses disk+superpoint+aliked; GV local features can be set with `--gv_features` (defaults to `--method` when not ensemble).
- `--use_geometric_verification` is removed; include `gv` in `--fusion_signals` to enable GV in fusion.
- In training/classification, Fisher usage is controlled by `--fusion_signals` (including `fisher` computes/uses Fisher vectors even without `--use_fisher`); `--use_fisher` remains relevant for count mode.
- `--pca_dim` controls PCA output dimensionality for Fisher vectors; non-default values are cached under a distinct suffix (e.g., `unsegmented_pca64`).
- For query-pipeline visualization, use `main.py --visualize_query_pipeline --ds <DATASET> --query_image <ID_OR_FILENAME>` (single) or `--query_images <ID1> <ID2> ...` (batch, comma-separated tokens also accepted). Batch mode writes one folder per query under `--assets_out_dir/<query_id>/` and a summary `--assets_out_dir/batch_manifest.json`.
- Query-pipeline assets include query vector signatures (`asset_query_global_signature.png`, `asset_query_fisher_vector_signature.png`), a local descriptor signature (`asset_query_local_descriptor_signature.png`), DB comparison panels (`asset_global_vector_database_panel.png`, `asset_fisher_vector_database_panel.png`), and predicted top-1 image tile (`asset_predicted_image.png`).
- Use `--assets_overview_mode` to generate simplified, larger-text ranking strips that show only rank + score + `CORRECT/WRONG` for quick thesis overview figures.
- In `--assets_overview_mode`, `asset_tier2_fusion_breakdown.png` is rendered as minimal-text per-candidate bar glyphs for Global/Fisher/Fused similarities.
- In `--assets_overview_mode`, candidate borders in ranking strips are color-coded by correctness (green correct, red wrong, gray unknown), and Tier-3 strip detail shows `inl` and fused score `f`.
- In `--assets_overview_mode`, `asset_predicted_image.png` is exported as the plain image tile (no text overlay), and global/fisher signature panels hide `dims=` footer text.
- Counting mode supports `calibrated` and `power` proposal modes over global/Fisher signals; shortlist/local-evidence proposal controls are removed (`--count_shortlist_B`, `--count_mix_alpha`, `--count_local_evidence`, `--count_local_mu`).

## Future: Minimal manual labeling
- For low-supervision deployments, prefer collecting **pair labels** (same/different) on a query’s **top-K shortlist** instead of full identity labels; these pair labels can train/calibrate Tier-2/GV/fusion calibrators efficiently.

- Fisher benchmark fitting is explicit (fit_fisher_model / transform_fisher_vectors). Test runs require a development-only fitted model and compatible rejection thresholds; legacy whole-collection APIs retain their behavior.
- The CzechLynx runner supports `--method ensamble` (DISK + SuperPoint + ALIKED) and explicit method lists with equal weights. It matches the existing weighted Fisher-vector sum, then L2-normalises for cosine retrieval/clustering. Defaults are PCA 128 and **256 GMM components per extractor**, with separate models fitted on the same permitted images (historical development gallery, or phase 2 fitting pool).
- Ensemble development writes `<out-dir>/fisher_bundle.json`; pass it as `--fisher-model` together with that run's `thresholds.json` for frozen testing. DISK-only thresholds/models cannot stand in for the ensemble. Compatible per-extractor and global caches are reused.
- Benchmark GV uses `--gv_features` (alias `--gv-features`), defaulting to DISK for ensembles or the single chosen extractor. Ensemble thresholds bind the GV configuration; development and test must agree. The runner normalises SuperPoint/ALIKED keypoint batch axes without changing legacy extraction APIs.
- Ensemble regression tests are in `tests/test_benchmark_ensemble.py`; test execution and real-data ensemble validation remain with the user.
- Official time_closed metadata has shared mixed-animal encounters. Overlap errors are the default; --overlap-policy purge-query records explicit exclusions. Never silently edit official split assignments.
- Missing geometric verification is a no-op in affinity refinement; genuine zero-inlier attempts may still suppress affinity.
- Generated CzechLynx data/caches live under data/czechlynx/ and reports under evaluations/czechlynx/; both are ignored by Git.

Masked crops are lossless PNGs with RGB (128,128,128) background plus aligned 0/255 PNG masks and checksummed pair receipts. Existing bbox/frame defaults and stable IDs remain unchanged.

Filtering uses original crop coordinates and nearest-pixel membership. Empty feature sets remain as zero Fisher vectors/skipped GV, with per-extractor retention counts in reports.
