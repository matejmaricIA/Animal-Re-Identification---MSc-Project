\chapter{Experiments and Results}
\label{chap:results}

In this chapter I will go over the final experimental evaluation of the proposed system. The experiments are divided into two parts:
(i) evaluation of the \textbf{classification (re-id) pipeline}, and
(ii) evaluation of the \textbf{population size estimateion pipeline} introduced in the Chapter~\ref{chap:population_size}.

\section{Classification Pipeline Evaluation}
\label{sec:results_class}

\subsection{Experimental protocol}
All classification experiments follow the closed-set identification protocol described in 
Chapter~\ref{chap:dataset}. A query image from the test split is assigned an identity label by 
comparing it to the labeled training split. The experiments use the same 
train/test split protocol as used in the MegaDescriptor baseline training for leakage control (\textbf{*} datasets) for datasets that MD was trianed on and for the rest time-aware splits or similarity-aware splits when time-aware wasn't available. 

The following methods are compared:
\begin{itemize}
    \item \textbf{MegaDescriptor baseline (Global only).} A strong baseline that uses only global 
    deep embeddings from the WildlifeDatasets toolkit~\cite{čermák2023wildlifedatasetsopensourcetoolkitanimal}. 
    In this thesis, the MegaDescriptor-L-384 model is used when reporting ``Global only'' results.
    \item \textbf{WildFusion baseline.} A calibrated fusion method proposed by 
    Čermák et al.~\cite{cermak2024wildfusionindividualanimalidentification}.
    \item \textbf{This thesis (Fisher).} Using only Fisher Vector similarity (Chapter~\ref{chap:feature_aggregation}) as
     the matching signal.
    \item \textbf{This thesis (Global+Fisher).} Late fusion of global embedding similarity and Fisher similarity.
    \item \textbf{This thesis (Fisher+GV).} A two-tier pipeline using Fisher similarity to shortlist candidates, 
    followed by geometric verification (GV) re-ranking.
    \item \textbf{This thesis (Global+Fisher+GV).} The full three-tier pipeline combining global embeddings, 
    Fisher similarity, and geometric verification.
\end{itemize}

To keep the comparison focused, I don't report each individual local feature extractor variant
 (DISK vs SuperPoint vs ALIKED) separately in the final table, but rather an ensemble of all three is tested.

\subsection{Metrics and Runtime}
Performance is reported using Top-1 accuracy, Top-5 accuracy and F1 score. Runtimes are reported in minutes for end-to-end evaluation logged by the evaluation scripts.

\subsection{Discussion}

From the results, several things can be noted:

\begin{itemize}
    \item \textbf{The proposed three-tier pipeline tracks WildFusion closely on most datasets, with a much better runtime--accuracy trade-off.} In mean Top-1 and F1, \textbf{G+F+GV} is within $\sim$1--2 pp of WildFusion but is substantially faster (42.53 minutes on average vs.\ 214.52 minutes for WildFusion).
    \item \textbf{WildFusion is strongest on SealID and SeaStarReID2023, while both approaches come close to perfect score on easier benchmarks.} WildFusion remains clearly stronger on SealID (Top-1: 97.60\% vs.\ 85.13\%) and is also better on SeaStarReID2023 (80.47\% vs.\ 77.21\%). 
     On ATRW and CZoo both pipelines are near perfect, so the differences are comparatively small.
    \item \textbf{ELPephants is the most difficult dataset tested and the method presented in this thesis performs the best.} On ELPephants, even the best configuration reaches only 54.46\% Top-1, but \textbf{G+F+GV} improves over WildFusion by \(\sim\)5 pp in Top-1 
    (54.46\% vs.\ 49.31\%) and \(\sim\)4.5 pp in F1 (49.71\% vs.\ 45.19\%). The large gap 
    to Global-only (13.66\% Top-1) and Fisher-only (20.79\% Top-1), together with the strong Top-5
     from F+GV (68.12\%), highlights that explicit local evidence and geometric consistency are essential on this benchmark. This makes sense because elephants don't have distinct fur/coat markings (like seals or tigers for example).
      Despite using GV, our run is still far faster than WildFusion (87.70 vs.\ 308.05 minutes).
      
\end{itemize}

\section{Population Counting Evaluation}
\label{sec:results_counting}

In this section we evaluate the population size estimation method as described in Chapter ~\ref{chap:population_size}. To address the problem of human error, we simulate it by flipping pairwise "human" answers with probability \(p\) (Chapter~\ref{chap:population_size}, Section~\ref{sec:labeling_error}). For all runs reported here I used \(N=50\) sampled vertices and \(M=500\) (except for the ELPephants dataset where \(N=100\) and \(M=1500\)) sampled neighbors per vertex and a strict confirmation with \(K=2\) consecutive ``same'' votes was applied.

\subsection{Discussion}
Tables~\ref{tab:counting_error_sweep} and~\ref{tab:counting_error_sweep_k1} show how the HITL-NIS estimator behaves as a function of the simulated human annotation error rate \(p\) and how it reacts to the increased confirmation strictness \(K\) and the underlying quality of the re-id signal:
\begin{itemize}
    \item \textbf{Human annotation noise causes a collapse towards underestimation.} As the chance of error increases, datasets rapidly fall from realistic estimates to very small counts with tight confidence intervals. This is a direct consequence of the extreme class imbalance among candidate pairs since there are far more ``different'' pairs than ``same'' pairs, so flipping answers with a probability \(p\) creates many false positive edges which create non-existent merges and underestimate the number of individuals.
    \item \textbf{Confirmation is critical, but still not a realistic assumption.} With \(K=2\) (meaning two confirmations needed) the collapse is significantly delayed, with some datasets giving a solid population estimation range with labeling error at 15\% (CowDataset, CZoo). It can be noted from the table~\ref{tab:counting_error_sweep} that datasets with a lower number of GT individuals tend to collapse slower than the ones with larger number (ATRW). Maybe even more important to mention it that this introduction of a random error rate is a rather naive assumption that labeling events are independent and that the person labeling the pairs always has a same chance of making an error. Intuitively it makes sense to me that a person making an error on a labeling pair would have a bigger change to repeat that error the second time around. 
    \item \textbf{Counting quality depends on Re-ID quality.} HITL-NIS relies on the underlying similarity model to propose informative candidate pairs so naturally, when re-identification is reliable, the process tends to perform better. For example, at \(K = 0\) ElPephants dataset was tested with the same \(N\) and \(M\) parameters as the rest of the datasets and even at error rate of 0\% the confidence interval did not include the GT, only when increasing the \(N\) and \(M\) in table~\ref{tab:counting_error_sweep} to 150 and 1500 respectively did it achieve somewhat usable results. This means that for that dataset, with the current system, the annotator would have to manually label ~220,000 pairs of images to get a reliable result (this is without counting on the repeated queries for the pairs labeled as ``same''), which is still just around ~5\% of the total possible pairs. 
\end{itemize}
