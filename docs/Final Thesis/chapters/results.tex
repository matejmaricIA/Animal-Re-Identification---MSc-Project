\chapter{Experiments and Results}
\label{chap:results}

This chapter presents the final experimental evaluation of the proposed system. The experiments are divided into two parts:
(i) evaluation of the \textbf{classification (re-identification) pipeline}, and
(ii) evaluation of \textbf{population size estimation} using Human-in-the-Loop Nested Importance Sampling (HITL-NIS) 
introduced in Chapter~\ref{chap:population_counting}.

\section{Classification Pipeline Evaluation}
\label{sec:results_classification}

\subsection{Experimental protocol}
All classification experiments follow the closed-set identification protocol described in 
Chapter~\ref{chap:dataset}. A query image from the test split is assigned an identity label by 
comparing it to the labeled training split. Unless stated otherwise, the experiments use the same 
train/test split protocol as used in the MegaDescriptor baseline training for leakage control (\textbf{*} datasets). 

\subsection{Compared methods and ablations}
\label{sec:results_classification_methods}

The following methods are compared:
\begin{itemize}
    \item \textbf{MegaDescriptor baseline (Global only).} A strong baseline that uses only global 
    deep embeddings from the WildlifeDatasets toolkit~\cite{čermák2023wildlifedatasetsopensourcetoolkitanimal}. 
    In this thesis, the MegaDescriptor-L-384 model is used when reporting ``Global only'' results.
    \item \textbf{WildFusion baseline.} A calibrated fusion method proposed by 
    Čermák et al.~\cite{cermak2024wildfusionindividualanimalidentification}. We report the baseline values from 
    their pipeline runs for the same datasets and splits where available.
    \item \textbf{Ours (Fisher).} Using only Fisher Vector similarity (Chapter~\ref{chap:feature_aggregation}) as
     the matching signal.
    \item \textbf{Ours (Global+Fisher).} Late fusion of global embedding similarity and Fisher similarity.
    \item \textbf{Ours (Fisher+GV).} A two-tier pipeline using Fisher similarity to shortlist candidates, 
    followed by geometric verification (GV) re-ranking.
    \item \textbf{Ours (Global+Fisher+GV).} The full three-tier pipeline combining global embeddings, 
    Fisher similarity, and geometric verification.
\end{itemize}

To keep the comparison focused, we do not report each individual local feature extractor variant
 (e.g., DISK vs SuperPoint vs ALIKED) separately in the final table.
  Instead, for each dataset we report the Fisher-based configuration used in the corresponding fused pipeline runs.

\subsection{Metrics and runtime reporting}
\label{sec:results_classification_metrics}

Performance is reported using \textbf{Top-1 accuracy}, \textbf{Top-5 accuracy}, and \textbf{F1 score}.
 Runtimes are reported as wall-clock minutes for the end-to-end evaluation run as logged by the scripts;
  results are therefore indicative of practical cost, including data loading and any cached feature reuse.

\subsection{Discussion}

Several consistent patterns emerge:
\begin{itemize}
    \item \textbf{WildFusion is the strongest overall baseline, but our full pipeline is competitive.} WildFusion achieves the best mean Top-1 and Top-5 across datasets and is best on most benchmarks, while the full three-tier pipeline (\textbf{G+F+GV}) is best on CowDataset and ELPephants and achieves the best Top-1 and F1 on Chicks4FreeID.
    \item \textbf{Geometric verification is most valuable on the hardest datasets.} On ELPephants, the full three-tier pipeline (\textbf{G+F+GV}) substantially improves Top-1 and F1 compared to using global embeddings or Fisher similarity alone, supporting the intuition that local geometric consistency is essential when global similarity is unreliable.
    \item \textbf{Accuracy gains come with large runtime costs.} Global-only evaluation completes in seconds, Fisher-based evaluation in minutes, while adding GV increases runtimes by an order of magnitude (e.g., \(\sim\)10--80 minutes for \textbf{G+F+GV}). The WildFusion pipeline is substantially more expensive in wall-clock time in our runs (typically \(\sim\)70--300 minutes), highlighting a practical trade-off between peak accuracy and evaluation throughput.
\end{itemize}

\section{Population Counting Evaluation}
\label{sec:results_counting}

\subsection{Experimental protocol}
We evaluate population size estimation using the HITL-NIS implementation described in Chapter~\ref{chap:population_counting}.
 To quantify the sensitivity to human mistakes, we simulate oracle label error by flipping pairwise oracle
  answers with probability \(p\) (Chapter~\ref{chap:population_counting}, Section~\ref{sec:labeling_error}). 
  Unless stated otherwise, runs use \(N=50\) sampled vertices and \(M=500\) sampled neighbors per vertex.
  We report results for strict confirmation with \(K=2\) consecutive ``same'' votes (Table~\ref{tab:counting_error_sweep})
   and additionally for \(K=1\) to show how quickly counting degrades under weaker confirmation (Table~\ref{tab:counting_error_sweep_k1}).
   ELPephants uses higher sampling budgets (\(K=2\): \(N=100, M=1500\); \(K=1\): \(N=250, M=1500\)).

In preliminary sweeps we observed that the choice of proposal variant did not lead to consistent differences in the final estimate at the reported budgets. For clarity, we therefore report a single configuration corresponding to the \emph{raw-score} proposal setting, and focus on the effect of oracle label noise.

\subsection{Discussion}

The results illustrate the core failure mode discussed in Chapter~\ref{chap:population_counting}:
\begin{itemize}
    \item \textbf{\(K=2\) is substantially more robust to labeling noise than \(K=1\).} With strict confirmation (\(K=2\)), several datasets remain correct up to \(p \approx 0.05\) (and up to \(p \approx 0.15\) on CowDataset and CZoo), before collapsing around \(p \ge 0.10\). In contrast, \(K=1\) typically fails already at \(p=0.02\), illustrating how quickly HITL-NIS can degrade without confirmation.
    \item \textbf{Failure is dominated by false ``same'' votes.} As \(p\) increases, estimates collapse toward very small values across datasets, consistent with the analysis in Chapter~\ref{chap:population_counting}: erroneous merges cause the sampler to underestimate the number of individuals.
    \item \textbf{Robustness comes at a runtime/oracle-cost premium.} Requiring a second confirmation vote increases oracle calls and runtimes (especially on larger datasets), but provides a dramatic gain in tolerance to realistic human error rates. In real deployments, the dominant cost would be human annotation time rather than compute.
\end{itemize}
