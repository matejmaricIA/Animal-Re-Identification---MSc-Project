\chapter{Experiments and Results}
\label{chap:results}

This chapter presents the final experimental evaluation of the proposed system. The experiments are divided into two parts:
(i) evaluation of the \textbf{classification (re-identification) pipeline}, and
(ii) evaluation of \textbf{population size estimation} using Human-in-the-Loop Nested Importance Sampling (HITL-NIS) 
introduced in Chapter~\ref{chap:population_counting}.

\section{Classification Pipeline Evaluation}
\label{sec:results_classification}

\subsection{Experimental protocol}
All classification experiments follow the closed-set identification protocol described in 
Chapter~\ref{chap:dataset}. A query image from the test split is assigned an identity label by 
comparing it to the labeled training split. Unless stated otherwise, the experiments use the same 
train/test split protocol as used in the MegaDescriptor baseline training for leakage control (\textbf{*} datasets). 

\subsection{Compared methods and ablations}
\label{sec:results_classification_methods}

The following methods are compared:
\begin{itemize}
    \item \textbf{MegaDescriptor baseline (Global only).} A strong baseline that uses only global 
    deep embeddings from the WildlifeDatasets toolkit~\cite{čermák2023wildlifedatasetsopensourcetoolkitanimal}. 
    In this thesis, the MegaDescriptor-L-384 model is used when reporting ``Global only'' results.
    \item \textbf{WildFusion baseline.} A calibrated fusion method proposed by 
    Čermák et al.~\cite{cermak2024wildfusionindividualanimalidentification}. We report the baseline values from 
    their pipeline runs for the same datasets and splits where available.
    \item \textbf{Ours (Fisher).} Using only Fisher Vector similarity (Chapter~\ref{chap:feature_aggregation}) as
     the matching signal.
    \item \textbf{Ours (Global+Fisher).} Late fusion of global embedding similarity and Fisher similarity.
    \item \textbf{Ours (Fisher+GV).} A two-tier pipeline using Fisher similarity to shortlist candidates, 
    followed by geometric verification (GV) re-ranking.
    \item \textbf{Ours (Global+Fisher+GV).} The full three-tier pipeline combining global embeddings, 
    Fisher similarity, and geometric verification.
\end{itemize}

To keep the comparison focused, we do not report each individual local feature extractor variant
 (e.g., DISK vs SuperPoint vs ALIKED) separately in the final table.
  Instead, for each dataset we report the Fisher-based configuration used in the corresponding fused pipeline runs.

\subsection{Metrics and runtime reporting}
\label{sec:results_classification_metrics}

Performance is reported using \textbf{Top-1 accuracy}, \textbf{Top-5 accuracy}, and \textbf{F1 score}.
 Runtimes are reported as wall-clock minutes for the end-to-end evaluation run as logged by the scripts;
  results are therefore indicative of practical cost, including data loading and any cached feature reuse.

\subsection{Discussion}

Several consistent patterns emerge:
\begin{itemize}
    \item \textbf{The proposed three-tier pipeline tracks WildFusion closely on most datasets, with a much better runtime--accuracy trade-off.} In mean Top-1 and F1, \textbf{G+F+GV} is within \(\sim\)1--2 pp of WildFusion (Table~\ref{tab:classification_results_final}), but is substantially faster in our runs (39.35 min on average vs.\ 214.52 min for WildFusion).
    \item \textbf{WildFusion is strongest on SealID and SeaStarReID2023, while both approaches saturate on easier benchmarks.} WildFusion remains clearly stronger on SealID (Top-1: 97.60\% vs.\ 85.13\%) and is also better on SeaStarReID2023 (80.47\% vs.\ 77.21\%). On ATRW and CZoo both pipelines are near saturation, so the differences are comparatively small.
    \item \textbf{ELPephants is the hardest dataset tested, and our full pipeline performs best.} On ELPephants, even the best configuration reaches only 54.46\% Top-1, but \textbf{G+F+GV} improves over WildFusion by \(\sim\)5 pp in Top-1 (54.46\% vs.\ 49.31\%) and \(\sim\)4.5 pp in F1 (49.71\% vs.\ 45.19\%). The large gap to Global-only (13.66\% Top-1) and Fisher-only (20.79\% Top-1), together with the strong Top-5 from F+GV (68.12\%), highlights that explicit local evidence and geometric consistency are essential on this benchmark. Despite using GV, our run is still far faster than WildFusion (87.70 vs.\ 308.05 minutes).
    \item \textbf{This structure is directly reusable for population estimation.} The HITL-NIS counting estimator evaluated in Section~\ref{sec:results_counting} operates directly on the same Global/Fisher similarity signals reported here, making it practical to run many oracle-in-the-loop iterations with a lightweight backbone (e.g., \textbf{G+F} averages 3.01 minutes). GV can then be reserved for final identification runs when additional accuracy is needed.
\end{itemize}

\section{Population Counting Evaluation}
\label{sec:results_counting}

\subsection{Experimental protocol}
We evaluate population size estimation using the HITL-NIS implementation described in Chapter~\ref{chap:population_counting}.
 To quantify the sensitivity to human mistakes, we simulate oracle label error by flipping pairwise oracle
  answers with probability \(p\) (Chapter~\ref{chap:population_counting}, Section~\ref{sec:labeling_error}). 
  Unless stated otherwise, runs use \(N=50\) sampled vertices and \(M=500\) sampled neighbors per vertex.
  We report results for strict confirmation with \(K=2\) consecutive ``same'' votes (Table~\ref{tab:counting_error_sweep})
   and additionally for \(K=1\) to show how quickly counting degrades under weaker confirmation (Table~\ref{tab:counting_error_sweep_k1}).
   ELPephants uses higher sampling budgets (\(K=2\): \(N=100, M=1500\); \(K=1\): \(N=250, M=1500\)).

In preliminary sweeps we observed that the choice of proposal variant did not lead to consistent differences in the final estimate at the reported budgets. For clarity, we therefore report a single configuration corresponding to the \emph{raw-score} proposal setting, and focus on the effect of oracle label noise.

\subsection{Discussion}

Tables~\ref{tab:counting_error_sweep} and~\ref{tab:counting_error_sweep_k1} illustrate how the HITL-NIS estimator behaves as a function of the simulated oracle error rate \(p\), and how this interacts with confirmation strictness \(K\) and the underlying quality of the re-identification signal:
\begin{itemize}
    \item \textbf{Oracle noise causes a characteristic ``collapse'' toward underestimation.} As \(p\) increases, most datasets rapidly transition from plausible estimates to very small counts with tight confidence intervals. This is a direct consequence of the extreme class imbalance among candidate pairs: there are far more ``different'' pairs than ``same'' pairs, so flipping answers with probability \(p\) injects many false positive edges, which in turn induces erroneous merges and therefore underestimates the number of individuals.
    \item \textbf{Confirmation is critical: \(K=2\) delays failure substantially.} Requiring two consecutive ``same'' votes dramatically reduces the probability of accepting a spurious edge (approximately from \(p\) to \(p^2\) under independence), which is why \(K=2\) remains correct up to \(p \approx 0.05\) on several datasets (and up to \(p \approx 0.15\) on CowDataset and CZoo), whereas \(K=1\) typically fails already at \(p=0.02\).
    \item \textbf{Counting quality depends on Re-ID quality.} HITL-NIS does not operate on ground-truth identity structure directly; it relies on the underlying similarity model to propose informative candidate pairs. When re-identification is reliable, the sampler concentrates oracle queries on genuinely ambiguous neighborhoods, producing stable degree estimates and confidence intervals that contain GT for moderate \(p\). Conversely, when Re-ID is weak, proposals become noisy and the estimator either becomes highly variable (wide CIs) or confidently wrong (collapsed estimates). This explains the behavior on ELPephants: in classification the best Top-1 is only \(\sim 54\%\) (Table~\ref{tab:classification_results_final}), and even with increased sampling budgets (Section~\ref{sec:results_counting}, protocol for ELPephants) the \(K=1\) setting fails to include GT already at \(p=0\), while \(K=2\) succeeds only at very low error rates and then collapses quickly as \(p\) increases.
    \item \textbf{Robustness carries an oracle-cost premium.} Increasing \(K\) improves tolerance to realistic human error rates but increases the required number of oracle interactions and therefore runtime (especially for larger datasets). In practice, the dominant cost is expected to be annotator time rather than computation, which makes confirmation-based strategies an important design choice for deployments.
\end{itemize}
